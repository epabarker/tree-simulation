# I1: the whole 2D core in Rust (ADR 0024)

## Question

Can the whole 2D simulation move to Rust, bit-identical to every golden, behind the same world interface, and the TypeScript core be deleted? What does it cost or save, per season, in the browser and natively, in each build? Which `Math` routines must be ported for parity?

## Setup

- **Order of the port:** one phase at a time, in the season loop's order (architecture.md's table): light, sample, allocate, grow, shed, girth, mechanics, commit, deaths. Each phase ran in Rust with the rest still TypeScript. A TypeScript world's trees crossed into Rust and back around the phase (`src/wasm/hybrid.ts` and `rust/wasm/src/bridge.rs`, both deleted at the end), and a side-by-side mode ran the phase in both cores and compared every column. A phase was done when every golden and the side-by-side matrix passed with it in Rust. The commits (one per phase):

- **Math:** `code/2026-10-29-i1/math-survey.ts` holds each routine the TypeScript core called against this Node's V8, 10⁶ inputs each (half in the core's range, half any bit pattern). Output: `code/2026-10-29-i1/math-survey.txt`.
- **Timings, Node** (VM, 4 cores, Node 24.22.2): `npm run bench` (7 cases, 100 seasons, best of 3, full snapshots) at c5dc8b0 for the TypeScript core, and at a1bc8cf for the Rust core, production and `--parity`. Raw JSON: `code/2026-10-29-i1/bench-node-{ts,production,parity}.json`.

### Snapshot

Before, the TypeScript builder made each array and the worker transferred them one by one. After, Rust builds one buffer and the page copies it out of linear memory once; every array is a view on the copy. **Headless Chromium, snapshotMs:**

| Wood | View | TypeScript | Rust |
|---|---|---|---|
| forest | lab (full) | 2.44 | 1.11 |
| forest | garden | 0.61 | 0.47 |
| mixed wood | lab (full) | 0.97 | 0.77 |
| mixed wood | garden | 1.13 | 0.59 |

In Node the two are level (forest 0.59 against 0.69 ms, full). There the TypeScript arrays are not transferred and the JIT builds them quickly, while the Rust figure includes the copy.

## Conclusion

- **I1 passes.** Every golden is bit-identical in the parity build, natively, in Node and in Chromium, and the production build holds its own goldens on all three. The TypeScript core is deleted; its code and goldens are at the tag `golden-2d-ts`, and its snapshots and checkpoints are recorded in `tests/fixtures/ts-core.json` to hold the Rust core to.
- **Cross-engine determinism is fixed.** Chromium went from 7 to 27 of 27, so the lab's seeds, shared links and `?forest=seed` now regrow the same forest in every browser. Phones remain to be checked.
- **The speed gain in the browser is modest:** production takes 0.74–0.77 of the TypeScript core's time a season in Chromium, and 0.65–0.93 in Node. Parity is slower than TypeScript in the browser (1.07–1.18×) and in Node (0.83–1.23×, mostly slower). Natively the step takes 0.44–0.72 of the TypeScript core's step in Node (its time less the snapshot). The gain I1 buys is determinism and a native core, not speed; the speed that matters (the 3D light) is G3's SIMD kernel.
- **The snapshot halves in the browser** for the lab's full view (2.44 → 1.11 ms on forest).
