## Checkpoint compatibility

ADR 0059 makes v3 append an aligned float64 counter per metamer after each tree's
bud columns. The native v1 planar conversion and v2 column reader remain. Their
unrecorded counter history starts at zero; migration cannot recreate it. New rows
whose counters are not allocated also write zero.

Tests save midway through a kShed=3 streak, restore, then require the same future
shedding and full saved bytes. A surplus restarts the streak. Counters follow
compaction and persist across multiple trees. The worker's `intoCheckpoint` now
retains them until serialization rather than freeing them as scratch. The existing
state-hash schema is unchanged and excludes counters; immediate hash equality alone
would miss the defect.

The frozen v2 fixture came from the pre-change writer (see its adjacent provenance
note). It has 45 metamers: **16,584 bytes → 16,944 bytes**, exactly **360 bytes** or
8 bytes/metamer. No visual garden change is proposed.

## Holly's exact deletion check

Both pre/post DAGs leave all holly vigour-reader gates closed in lone and actual
garden contexts: no vigour drop, light orthotropy or Tvig consumer. The source
overrides and fitted species lose only `r2.vigourTreeLo/Hi`; beech's keys remain.
The adopter starts from the current whole patch, so explicit generator cleanup is
needed to prevent retained legacy fields from surviving regeneration. A second
adoption/export reproduced the same bytes and kept the keys removed.

The before binary and effective params were captured before implementation; the
after binary was rebuilt. The harness refuses unrelated effective-param differences,
runs seeds 1–20 for 150 seasons with three workers, and compares every final hash.
Only root holly effective keys and its own species overlay differ. This confirms
**no observed effect of this deletion at this setting**, not arbitrary settings
where another rule could open the vigour gates.

```bash
PATH="$HOME/.cargo/bin:$PATH" uv run --project analysis python analysis/experiments/day3_holly_keys.py \
  --before-binary runs/day3-step2/before-treesim \
  --before-params runs/day3-step2/before-params/species_effective_lone.json \
  --out runs/day3-step2/holly --jobs 3
```

The frozen inputs, binary digests, exact before/after params, per-seed hashes and run
provenance are retained under ignored `runs/day3-step2/`; only summaries are committed.
To reproduce from a fresh checkout, build native and WASM at 8995f73 first and dump
its lone params with `dump_effective.ts`, preserving that native executable before
building this step's code. The registered script never silently substitutes a
