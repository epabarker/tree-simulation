# Overseer review and plan (2026-11-05)

_The user asked for an overseer: step back from the current fits, judge them against the project's goal, and
find the shortest path to success. This note is that review. It changes no ADR; the decisions in §6 are the user's._

## 1. The goal
An interactive tree simulator for edbarker.dev in which **beautiful behaviour emerges from simple local rules**
(AGENTS.md). The user's bar, set 2026-10-30 and confirmed 2026-11-02, was: the mixed wood looks right in the
garden, in depth; it runs within the phone's budget; and floor, H/D and crown base hold as 20-seed evidence.
After that bar come the species' looks (STATUS's "form list"). Fidelity to data is a means to good looks, not
the goal itself.

## 2. Where we are
- **The bar is met, and the 3D garden is live.** `garden-v0.15.0` was released from `3d-port` (a417437), site
  PR #7 merged 2026-11-02, and edbarker.dev serves `garden/0.15.0/garden.js`. STATUS still says "the live site
  stays on 0.14.0", and the devlog never recorded the release. On the phone the garden "works great"; the
  hour-long soak was never done.
- **Since 2026-11-03: reference fidelity** (ADR 0049), 60 commits on `claude/reference-fidelity`, not merged.
  - Built: a converter, `describe()`, gates a–c, Level 0 targets, and a Level 1 fitter.
  - Results: Level 0 gives beech 9/20, oak 0/20 and birch 0/20. The beech pilots v3 and v4 fit the medians well
    (loss 6.7 → 1.6, held-out descriptors 19–20 of 20) and **fail only on spread**: the trees vary too little
    from one another (ADR 0053).
  - **Nothing has been accepted into any species**, so the garden looks exactly as it did on 2026-11-02.
  - One core change has a visible effect: ADR 0054 (every tree used to lean +x). It is unmerged.
- **The live garden, as a visitor sees it** (forest no. 12, years 34–39, laptop): three near-identical,
  flat-topped goat-willow umbrellas, evenly spaced and with the same understory beneath each. It reads as a
  savanna. Willow, rowan and holly have no QSMs, so reference fidelity can never reach them.

## 3. Diagnosis: why it feels like a rabbit hole
1. **Instrument churn.** Gate c went v1 → v3.2, Level 0 v1 → v2, and the registrations v1 → v6, with v7 next.
   Each failed gate produced a new descriptor, audit or ADR rather than a decision.
2. **A serial chain before the next fit:** the arch ADR, then Level 0 for every species, then gate c's
   simulated rows, then v7. That is four sessions before beech is fitted again.
3. **The terms that fail are not what the eye sees.** On the like-for-like sheet, the visible gaps are narrow
   bottle-brush crowns and lean. The gate fails on limbUpturn's between-tree spread.
4. **No exit criterion.** Nothing says when to adopt a fit, or when to pause the method.
5. **STATUS steers every session into gate detail.** Its Direction paragraph runs to about 6,000 characters of
   gate versions and loads into every session.

## 5. The shortest path: two tracks, time-boxed
**Track G, the garden (what visitors see):** contact sheet → judging pass → overrides → merge ADR 0054 →
release 0.16.0 → soak. About 2–3 sessions. This addresses STATUS's whole after-shipping form list by the
route that has worked so far (ADR 0029 and the overrides).

**Track F, beech fidelity, with a bound on it:**
1. The user rules on ADR 0053: is a measured, frozen per-tree draw allowed under ADR 0049 §2?
2. If yes: implement the draw and run its probe (one session), then v7 on beech only (one night), then the gate.
   - Pass: render the fit beside the hand in the garden; the user judges; adopt it if it looks better.
   - Fail: stop.
3. If the ruling is no, or v7 fails: **pause reference fidelity.** Beech keeps the hand's look. The
   infrastructure stays and is recorded as such.
4. **Exit criterion:** at most 3 sessions and 1 overnight fit, from the ruling to an adopted beech or a pause.
5. **Cut unless v7 provably needs them:** the arch-magnitude ADR, Level 0 for every species, gate c's simulated
   rows, and the provenance audit's proposals. The first agent on track F checks whether v7 needs them.

**Overseer's rules for agents:**
- No new descriptor, registration, ADR or audit without the overseer's OK.
- Each brief has a stop condition.
- Reports are at most 300 words.
- Code-writing agents work in worktrees.
- Only the main session writes `docs/`.
- No agent uses a browser pane. Visual checks run in headless Firefox (puppeteer-core) with a fixed list of
  captures and a timeout.
