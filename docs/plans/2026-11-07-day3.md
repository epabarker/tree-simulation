## 1. What the DAG gives us

**It is current.** `build_dag.py` was built at c6b60df. No file under `rust/core`, `src/core` or `analysis/fit/hand-overrides.toml` has changed between c6b60df and this branch's HEAD (b96fc2a). Against `3d-port` the only core difference is #64's `sidesZ`.

**Dead levers, certain.** A lever is dead when every path from it is closed by a gate. The sweep agreed on all 17 swept params: `c5.T` was the only bit-identical one.
- **Dead everywhere:** `c5.T` (carbon shedding never reads it); `c1.branchAngle`, `c1.phyllotaxis`, `c3.lambda`, `c4.eta` (R2's levels supply them); `r1.qHalf` (linear response); `o2.sway / maxSway / pAbr` (o2 off).
- **Dead in the lone tree only:** all of R5 and `r2.relayCrowd` (no neighbours), o4, `o2.stormLoad`.
- **Dead by species:** the relay and fork knobs in hornbeam, birch, oak, rowan and willow (relay off); the vigour and light-orthotropy knobs everywhere but beech. Holly's `vigourTreeLo/Hi` have no reader at all: ruling 7.
- **Use:** never spend a run on these. Each deletion of a dead key is checked by bit-identical goldens.

**Height has a clean dial; form does not.** The cases below are species × param × season × outcome where the −10% and +10% medians are both beyond the base's seed spread and of opposite sign (3 seeds, lone). This is a stricter count than the DAG note's 69 of 272, which counts sign agreement only.

| outcome | cases out of 272 each |
|---|---|
| height | 17 |
| W/H | 7 |
| dome index D | 1 |

- **`r1.maturity` is a height cap where the reproductive sink is strong.** Its one reader (`r1.rs`, line 108) diverts `fRep` of net production once height ≥ maturity. In the five species with `fRep` 0.8 (holly, hornbeam, oak, rowan, willow), lone height at 150 sits at about a quarter of maturity in every one, consistent with maturity being a height in grid cells. There, ±10% of maturity gives about ±10% of height (1.4–3.4 m), monotone and beyond noise at 100 and 150; willow at 150 only. That is the lever A3 used. A new species' height (sycamore, ash) can be set by solving for maturity, then confirmed on 20 seeds.
- **Beech, birch and maple have a weak sink** (`fRep` 0.1, maturity 30–40, effective params dumped 2026-11-07), crossed early and far below their heights. There maturity is live but weak, and ±10% mostly reshuffles. Beech's reversed sign at 150 (−10% gives +1.7 m, +10% gives −0.9 m) is most likely that noise; birch and maple show nothing beyond spread. Their height is set by other levers (trunk λ for birch, ADR 0057).
- **Trunk λ (`r2.levels.0.lambda`)** moves W/H beyond noise in hornbeam and oak; `levels.1.lambda` moves oak's W/H the other way. These are oak's live form knobs if ruling 4 is "keep working".
- **D, the dome index, has no reliable single-knob lever** at ±10% on 3 seeds. Form work on D needs either ≥ 20-seed tests of a few DAG-chosen knobs, or a measured mismatch that justifies a mechanism (policy rule 4). One-knob-at-a-time searches on D will mostly chase noise.

**Why seeds are expensive here.** Randomness is keyed by birth id, so a knob that changes how many shoots grow reshuffles every later draw. Pairing runs by seed probably buys little (untested: the correlation between base and patched runs of one seed has not been measured), so the cost of a claim is seeds. The 20-seed rule stands.

## 2. Where it is thin

- **Hand-written.** The edge table is read from the code by hand. It will rot when a principle changes, and nothing checks it yet.
- **Lone only.** The swept effective params come from the lone trial. The stand's dead-lever table is assumed from the forest preset, not dumped from the garden's world. The garden is a stand.
- **The stand loops are unswept.** L8 (neighbours: R5, the relay gate) and L9 (demography: o4) carry every open box problem: crown base, floor light, beech in shade, composition. The sweep has no crown-base, floor or survival outcome.
- **Coverage.** 17 of roughly 100 params, 3 seeds, ±10%. `sweep_effects.py` has real bands for only beech, hornbeam, birch and oak, so holly, maple, rowan and willow carry no band flags.
- **Candidates change the graph.** N3's oak turns the relay on, which opens gates that were closed in the sweep's oak rows. The sweep does not describe the candidate; the DAG must be re-evaluated on its params.
- **Reach separates nothing.** L1 and L2 connect every live knob to every outcome. The DAG prunes and explains; it does not rank.

## 3. Making it durable (proposed for step 1, housekeeping)

1. **Promote the tools beside `evidence2.py`:** `build_dag.py`, `dump_effective.ts` and `sweep_effects.py` into `analysis/treesim/`, pinned to the commit they read. `build_dag.py` reads `species_effective_lone.json`, which is not committed, so the tool cannot be re-run from the repo today: commit it, or have the tool regenerate it through `dump_effective.ts`.
2. **An empirical dead-override check.** For each species, perturb each key its overrides set and compare `hash.txt` with the base, on a full 150-season lone run and on a stand run long enough for the canopy to close. Short runs would wrongly call late-acting keys dead: maturity, `r6.lifespan`, aged set points, the relay age. A bit-identical hash means the key is dead at that setting. This is measured, never stale, and would have caught holly's vigour keys. It runs on demand or nightly, not in `npm run check`.
3. **A staleness check for the hand table:** a Python test that greps each principle file for the params it reads and fails when one is missing from the edge table.
4. **Dump the garden's stand params** per species (through `dump.ts`) and re-evaluate the gates, so the stand dead-lever table is measured.
5. **Add "update the DAG" to `/implement-principle`'s checklist** when a principle's reads or gates change.
6. **A knob card per tuning step,** in that step's section of this file:

   ```text
   knob:              <dotted path>, species, context (lone / stand)
   live?              DAG gate open at the candidate's params (yes / no, why)
   sweep sign, size:  <from sweep_effects.csv, or "not swept">, against base spread
   threshold risk:    near λ 0.5, hJ, maturity, or a known flip (hornbeam dLambda)
   seeds:             20 (fresh seeds 21-40 for held-out)
   ```
