# M12 review: performance, realism and the page (2026-10-27)

The user agreed that this session counts as M12, the review that comes before any work beyond the build order. The goals it served were:
- **A. Performance:** smooth on phones, bigger worlds, fast first paint.
- **B. Realism:** botanical form, motion and physics, and the seasonal cycle. The simulation stays 2D.
- **C. A home page:** the simulation becomes the home page of edbarker.dev.

Three read-only surveys covered performance, realism and the page. The findings below led to milestones M13–M21 (ROADMAP).

## Scope and limits

**Covered:**
- the season loop, the light models and the worker/page path, for cost;
- the spec, ADRs, experiments and known issues, for realism;
- the page, the build and deployment, for the home page.

**Not covered:** the ROADMAP's M12 row also asked for a line-by-line audit of core correctness and of test strength. That audit was not done here. It is folded into two later milestones, and both add what they find to this document:
- **M13** reads every hot loop while making golden-safe refactors. Unchanged goldens are its proof.
- **M19** adds the missing §8 ablation tests.

## Decisions (user, 2026-10-27)

1. **The simulation is the page.** The name, a few links and a short "what is this" sit over a living forest.
2. **Site:** the private repo `epabarker/edbarker-dev` (Astro 7, Tailwind 4, Cloudflare Workers static assets, `https://edbarker.dev`). The garden reaches it as a versioned GitHub Release, copied into the site's repo ([ADR 0014](../decisions/0014-home-page-delivery.md)).
3. **Realism** means botanical form, motion and physics, and the seasonal cycle. There will be no 3D slab.
4. **Performance** means three things: smooth on phones, bigger worlds, fast first paint.
5. **The home world** is a mixed forest with succession. It needs species per tree, which gets its own ADR at M19.

## Findings

### Performance

| Finding | Where | Planned |
|---|---|---|
| The sky sweep is O(K·W·H) and runs over every row, including the empty sky above the canopy. Each cell calls `Math.exp` once per direction | `light/sky-sweep.ts` `compute`, `sweep` | M13 (golden-safe row bound and exp skip) |
| Periodic sides sweep shallow rays ⌈3H/(rise·W)⌉ + 1 laps: ≈ 27 grid sweeps instead of 7 on a 210 × 130 ring, the "≈ 2.5×" of ADR 0013 | `sky-sweep.ts:191` | M18 (row-marched sweep; changes goldens) |
| `junctionExponents` builds child lists and runs 60 bisection steps per junction for every snapshot. This is the largest cost outside the simulation | `snapshot.ts:126`, `c6-girth.ts:48` | M13 (on request only) |
| Allocation every season: `trees.filter`, a closure and a spread per metamer under R5, a sorted JS array in `crownTopLight`, `Object.values` on every `Table.add`, a fresh `oldToNew` in `compact` | `season.ts`, `c5-shedding.ts`, `soa.ts` | M13 |
| `isRemoved` scans the event log for each tree. O4 checks every seed against every tree, and dead trees stay in `world.trees` forever | `world.ts:122`, `o4-stand.ts:67` | M13 |
| `seasonMs` excludes the snapshot build, so the HUD understates the worker's cost | `sim.worker.ts:27` | M13 |
| Each tween frame rebuilds geometry on the CPU (trig per metamer), and `upload` reallocates GPU buffers through `bufferData` | `scene.ts:296`, `webgl2.ts:442` | M15 |
| Each snapshot allocates a new `Geometry` and runs `computeGeometry(1)` twice. The shade texture is uploaded even when the overlay is off | `scene.ts:183`, `webgl2.ts:374` | M15 |
| The page uses a pull loop, so the worker sits idle while the page tweens | `main.ts:110,198` | M15 (pipelining) |
| Chart rows grow without limit, and Plot redraws them all | `charts.ts:41` | M15 |

**Determinism constraint:** `hashWorld` hashes the raw bytes of every column of every tree, so any change to the order of float operations changes the goldens. Each optimisation is therefore classed as golden-safe (goldens unchanged are the proof) or golden-changing (an experiment shows behaviour unchanged within noise, then `golden:update`).

### Realism

| Finding | Source | Planned |
|---|---|---|
| The species presets still switch off R1, R3, R4 and R5 | `presets.ts` `SPECIES_PRE_R1` | M20 |
| `Params` apply to the whole world, so there are no per-tree species and no mixed forest | `params.ts` | M19 (ADR 0015) |
| R5 reads the tree's own shade (there is no far-red field), so open-grown trees grow taller | STATUS, M10 note | M19 |
| Breakage never fires: stress wood keeps σ ≤ σ_target, and there is no wind | M10, ADR 0011 | M16 (O2 storms) |
| Sagging limbs sink below the ground | `r3-mechanics.ts` | M16 |
| Acrotony κ (R2) is deferred, so no leader ever loses top position and there is no true decurrent crown | ROADMAP, M7 note | M19 |
| §10 targets with no metric: branch angle by order, crown ratio, bud-break fraction, length–diameter, leaf/stem area, Kothari's regression | `metrics.ts` | M19 |
| §8 ablations with no test: equal sharing loses in competition, ξ = 0, constant λ, pooled light (no such mode exists) | spec §8 | M19 |
| Bimodality in self-thinning is marginal; O2 barely matters | M11 note | M20 (watch for it with storms and species) |
| No within-season life: no flush, autumn, leaf fall or wind | page | M16, M17 |

### Page

| Finding | Where | Planned |
|---|---|---|
| The page is a lab console with no canvas-only mode | `index.html`, `main.ts` | M14 (`mountGarden`) |
| The first tap of a double-tap fells a tree | `render/input.ts:79` | M14 |
| The wheel handler calls `preventDefault`, and `touch-action: none` blocks page scrolling | `input.ts:94`, `layout.css:129` | M14 (fixed camera) |
| The WebGL context is opaque (`alpha: false`), so a host page cannot show through | `webgl2.ts:277` | M14 |
| `theme.ts` reads its tokens from `:root`, not from the host element | `render/theme.ts` | M14 |
| Reduced motion only stops autoplay | `main.ts:39` | M14, M21 |
| The demo URL is unreachable (the parked custom-domain problem) | STATUS | Moot once the lab is served at `edbarker.dev/lab` (ADR 0014) |

## Triage: milestones M13–M21

| # | Track | Milestone |
|---|---|---|
| M13 | A | Benchmark harness (`npm run bench`, phase timings) and golden-safe core and worker speed-ups |
| M14 | C | `mountGarden` embed, a garden build and release, and a first home page on edbarker.dev |
| M15 | A | Renderer and phone performance, worker pipelining, adaptive quality |

| M18 | A | Row-marched light sweep (changes goldens); bigger worlds shaped to the viewport |
| M19 | B | Species per tree (ADR 0015); R5 neighbour shade; acrotony; the missing §10 metrics and §8 ablations |
| M20 | B | Species calibrated on patterns (birch, oak, beech, willow, conifer); the succession forest `garden` |
| M21 | C | First paint (checkpoint and poster), art direction, accessibility, launch |

**The order is chosen as follows:**
- Measuring comes first.
- A walking skeleton of the home page goes live early, so phone performance is measured in the real context.
- Page-only beauty costs no goldens.
- The light change that alters goldens lands before species calibration, so the calibration isn't undone afterwards.
- Launch polish comes last.
